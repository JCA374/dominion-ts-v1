Study this project

For someone who wants to learn from this project rather than follow it: what to read in which order, the ideas you need, the words we use, how to run it yourself, and a few exercises.

Reading order

  1. Overview, then Results: what is being compared and the current numbers (10 min).
  2. The teacher tab: how one question is graded (10 min).
  3. c/ts.c: rollout(), bv_grade(), ts_grade_sh(), bv_advise() (30 min).
  4. match.py and queue.txt: how an arm is played and scored (10 min).
  5. bv-v1's site for where the teacher came from; sg-v1's for why training c2 further did not help.

Key concepts

Flat Monte Carlo search — score each move by playing many random continuations with a fixed policy and averaging. Here: every candidate buy or action, c2 continuing. People forget it is only as good as the rollout policy: it finds moves that are good if c2 plays the rest.
Common random numbers (pairing) — give every candidate the same random deal, then compare differences. The difference between two options is much less noisy than either value. Used in the SE of the override gate.
Determinization — hidden information handled by dealing the unknown cards at random each draw, then searching as if the deal were known. Its known flaw (strategy fusion) is small here because the rollout policy does not peek.
Bias against variance — value-net leaves cut variance (and cost) but add the value net's errors. The match decides which wins at a fixed budget.
Successive halving — a best-arm identification method: equal rounds, drop the worse half each time. It spends the budget where the decision is.
Winner's curse — the best of many noisy options looks better than it is. The margin and z gate protect against overriding the net on noise.

Reproduce it

git clone --recursive https://github.com/JCA374/dominion-ts-v1 && cd dominion-ts-v1
python -m venv .venv && .venv/bin/pip install numpy        # (this repo uses rl-v3's venv)
.venv/bin/python experiments/equiv.py --lib ts              # builds ts.so; with options off = bv-v1's teacher
.venv/bin/python experiments/leaf_check.py --games 4        # ~4 min: value leaves vs full rollouts
.venv/bin/python match.py --name try --act 1 --k0 32 --k1 32 --leaf 4 --margin 0.02 --z 2 --obs 1 --opp c2 --stream ts1 --kingdoms 20 --workers 4

The last command plays 40 games (about 10 minutes) and writes results/match_try.json: expect a score above 50% with a wide interval.

Exercises

  1. Easy. Run leaf_check with D = 1 and D = 16. Expect D=1 to be very cheap but rank options poorly, D=16 nearly as costly as full rollouts.
  2. Medium. Turn off pairing: give each candidate its own seed in draw_all. Measure the SE of the gain at the same K: expect it several times larger and far fewer overrides.
  3. Medium. Change the gate (margin 0 / z 1) at 128 draws and play 100 kingdoms: more overrides, but do they win more?
  4. Hard. Use a different rollout opponent (c1 or the GA) while playing against c2: how much of the gain depends on knowing the opponent?
